API

BOLDTrace.BOLDTrace — Module
BOLDTrace

Identification of ASVs through the BOLD Systems v5 identification engine, LCA assignment, traceability of the BOLD reference records used, attribution to the people who identified the reference specimens, usage counters and reproducible exports, with a web interface built on Genie.jl.

Pipeline: read_asvs → run_analysis (BOLD engine, portal metadata, LCA.lca) → tables (assignment_table, reference_usage, taxonomic_attribution) → record_analysis! → export_analysis. serve starts the web application.

Analysis

BOLDTrace.Analysis — Type
Analysis

Result of run_analysis or analyze_hits: identifiers (id, fingerprint), created_at (UTC), project, user, the input, LCA params, accept_rank, data source (provenance of the BOLD data), one LCAResult and the MatchRows per unique sequence (results, matches), the references by key, non-fatal errors, and the downloaded data (hits from the identification engine, portal records or nothing), kept so that reanalyze can recompute the LCA without contacting BOLD again.

source
BOLDTrace.MatchRow — Type
MatchRow

One match of a unique query sequence: the reference key, percent identity, coverage, align_length, the LCA decision (included, reason) and dissent, the rank at which a selected reference disagreed with an assignment accepted by majority (nothing otherwise), and lineage, the classification of the reference reported by BOLD with this hit (the one used by the LCA). Hits of one analysis may classify the same reference differently (e.g. one from an old checkpoint): see reference_conflicts.

source
BOLDTrace.ReferenceRecord — Type
ReferenceRecord

A BOLD reference record used as a match. key is "<process_id>|<marker>" (the portal has one record per specimen and marker). Fields from the identification engine: process_id, marker, bin_uri, taxid, lineage. Fields from the portal (missing when metadata were not retrieved): record_id, sequence_hash (SHA-256 of the normalized nuc), identified_by (verbatim), identification, identification_method, identification_rank, institution (storing institution, never used for attribution), recordsets (BOLD projects/datasets), voucher_type, museum_id, sequence_upload_date, species_reference.

BOLDTrace.reanalyze — Function
reanalyze(a::Analysis; params = a.params, accept_rank = a.accept_rank,
          project = a.project, user = a.user) -> Analysis

New analysis computed from the data already downloaded for a (BOLD hits and portal metadata): no request to BOLD. Use it to try other LCA parameters. The provenance keeps the original data source and retrieval date and records reanalysis_of = a.id. The BOLD library and search mode cannot change (they decide which hits exist): a lower min_identity than the minimum of the search mode (e.g. 94 % in rapid mode) finds no new hits.

BOLDTrace.run_analysis — Function
run_analysis(input::InputSet; project = "default", user = "", params = LCAParams(),
             accept_rank = :phylum, db = :animal_public, mode = :rapid,
             engine = IDEngine(), checkpoint = nothing, metadata = true,
             portal_url = "https://portal.boldsystems.org",
             progress = msg -> nothing) -> Analysis

Identify the unique sequences of input with the official BOLD v5 identification engine (BOLDassignment.bold_identify), retrieve the metadata of the matched records from the BOLD portal API (metadata = true) and compute the LCA of every sequence.

A failure of the portal does not stop the analysis: references keep the fields of the identification engine, the failure is listed in errors and in the provenance. checkpoint (a directory) stores the raw engine result of every sequence and makes interrupted runs resumable; the provenance (source["hits_retrieval"]) tells, for each sequence, whether its hits were queried now or reused from the checkpoint and when they were retrieved (checkpoint file date). progress receives short status messages (used by the web interface).

BOLDTrace.read_asvs — Function
read_asvs(path_or_io; name = basename(path), min_length = 100,
          max_records = 100_000) -> InputSet

Read and validate a (multi-)FASTA file with FASTX.

Every record keeps its original identifier. A record is rejected, with an error message and without stopping the others, when its sequence is empty or contains characters outside the IUPAC nucleotide alphabet, or when its identifier repeats an earlier one with a different sequence. Warnings, which keep the record, are given for sequences shorter than min_length (the BOLD engine requires an overlap of at least 100 bases), repeated identifiers with the same sequence and sequences that are more than 5 % ambiguous bases. Identical sequences are recognized after normalization and grouped in unique. A file that is not valid FASTA throws ArgumentError.

source
BOLDTrace.sequence_hash — Function
sequence_hash(seq) -> String

Stable hash of a nucleotide sequence: hexadecimal SHA-256 of the sequence normalized with BOLDassignment.normalize_sequence (no whitespace or gaps, upper case, U → T). Identical sequences always get the same hash, whatever their case, gaps or line wrapping.

LCA (BOLDTrace.LCA)

BOLDTrace.LCA — Module
LCA

Lowest common ancestor of the reference matches of one query sequence. Independent of BOLD: matches are plain values with identity, coverage, alignment length and a lineage.

source
BOLDTrace.LCA.LCAParams — Type
LCAParams(; min_identity = 90, min_coverage = 80, max_delta = 1.0,
          max_matches = 100, min_align_length = 0, min_agreement = 100,
          rank_cap = true, rank_thresholds = DEFAULT_RANK_THRESHOLDS,
          ranks = DEFAULT_RANKS)

Parameters of lca:

  • min_identity: minimum percent identity of an admissible match;
  • min_coverage: minimum percent of the query covered by the match; a match with unknown coverage is excluded when min_coverage > 0;
  • max_delta: maximum identity difference (percentage points) from the best admissible match for a match to enter the LCA set;
  • max_matches: maximum size of the LCA set (closest matches first);
  • min_align_length: minimum alignment length in bases (0 = not used; a match with unknown length is excluded when it is positive);
  • min_agreement: minimum percent of the selected references identified at a rank that must carry the most frequent name for that rank to be assigned. 100 (default) is the strict LCA: one discordant reference stops the assignment. A lower value, e.g. 95, tolerates a few discordant references (probable misidentifications in the database): they are flagged as dissenting and leave the deeper ranks. Must be above 50 (a strict majority); ties for the most frequent name always stop;
  • rank_cap: when true, the assignment stops above the first rank (from the top) whose rank_thresholds value the best admissible identity does not reach (e.g. no species below 97 %), even if the LCA set agrees further. The lineage never skips a rank, also with thresholds that do not increase with depth.
source
BOLDTrace.LCA.LCAResult — Type
LCAResult
  • status: :assigned, :no_matches (nothing retrieved), :result_missing (set by the analysis, never by lca: BOLD did not return the result of the sequence, so its matches are unknown), :no_admissible_match (all matches filtered out) or :unresolved (the LCA set does not agree even at the first rank);
  • taxon, rank: deepest assigned taxon and its rank (nothing unless assigned);
  • lineage: assigned name for each rank down to rank;
  • agreement: for each rank of lineage, percent of the selected references identified at that rank (and consistent with the ranks above) that carry the assigned name;
  • dissent: one entry per input match: the rank at which a selected reference disagreed with an assignment accepted by majority (min_agreement < 100), otherwise nothing;
  • lca_rank: deepest rank supported by the LCA set before the rank cap;
  • rank_capped: whether the rank cap made the assignment shallower;
  • best_identity, best_coverage: of the best admissible match;
  • n_matches, n_admissible, n_selected;
  • decisions: one MatchDecision per input match, same order;
  • flags: notes such as "incomplete_taxonomy:species", "discordant:genus", "majority:species" (assigned with dissenting references), "inconsistent_hierarchy:genus", "identical_reference_sequences_discordant", "truncated_at_max_matches".

The rank is the depth of agreement of the selected references, not a statistical confidence.

MatchDecision

source
BOLDTrace.LCA.lca — Function
lca(matches, params = LCAParams(); valid_name = (rank, name) -> !isempty(strip(name)),
    sequence_hash = nothing) -> LCAResult

Lowest common ancestor of matches (a vector of Match):

  1. matches below min_identity, min_coverage or min_align_length are not admissible;
  2. the best admissible match is the one with the highest identity;
  3. admissible matches within max_delta of the best form the candidate set, ordered by identity, then coverage (descending), then identifier, and cut to max_matches;
  4. ranks are visited from the most general: at each rank the most frequent name among the selected references identified at that rank is assigned if it is carried by at least min_agreement percent of them (100 = all: strict LCA); otherwise, or on a tie, the assignment stops at the previous rank. References with another name are dissenting: they are recorded in dissent and leave the deeper ranks;
  5. a reference not identified at a rank (name missing, or rejected by valid_name, e.g. Genus sp.) does not vote at that rank or deeper ones, but still supports the ranks above; if no selected reference is identified at a rank, the assignment stops there (incomplete taxonomies never force a deeper rank);
  6. with rank_cap, the result is cut to the deepest rank allowed by the identity of the best admissible match.

sequence_hash, when given, is a vector with the hash of each reference sequence (nothing when unknown): selected references with identical sequences but different names at the assigned or next rank are flagged.

source

BOLDTrace.LCA.DEFAULT_RANK_THRESHOLDS — Constant

Minimum identity (percent) of the best admissible match for an assignment to reach each rank when rank_cap = true (same values as BOLDigger3 and BOLDassignment).

BOLDTrace.reference_usage — Function
reference_usage(a::Analysis) -> Vector{NamedTuple}

One row per reference record with three descriptive counts over the unique sequences of the analysis:

  • retrieved_usage: sequences whose BOLD matches include the record;
  • lca_participation: sequences whose LCA set includes the record;
  • assignment_contribution: sequences with an accepted assignment whose LCA set includes the record.

These counts describe participation; they do not show that a record was necessary for an assignment. Sorted by decreasing participation. When the hits of the analysis classify a record differently (reference_conflicts), taxon and rank list all the classifications, separated by |.

source
BOLDTrace.taxonomic_attribution — Function
taxonomic_attribution(a::Analysis) -> Vector{NamedTuple}

Aggregate statistics per taxonomic identifier, i.e. the verbatim BOLD identified_by value of the reference records. Names are not normalized or merged: similar spellings stay separate, a value listing several people stays one entry. Records without identified_by are grouped under "(not provided)". Contribution is never assigned to the sequencing laboratory, the storing institution, the uploader or the project manager.

Columns: identifier, orcid (empty, reserved for a future normalization), n_records (distinct records among the matches), n_asvs_supported (unique sequences with an accepted assignment whose LCA set includes one of the identifier's records), n_lca_participations (record × sequence pairs in LCA sets), n_taxa (distinct taxa of the identifier's records) and fractional_credit, an experimental participation indicator: each accepted sequence distributes 1 equally among the distinct identifiers of its LCA set. It is not a measure of scientific merit.

BOLDTrace.record_analysis! — Function
record_analysis!(store, a::Analysis) -> NamedTuple

Store the analysis, its per-sequence results, the reference records and one identification event per (unique sequence, reference record). An analysis with the same fingerprint (same project, user, sequence set, BOLD database and mode, LCA version and parameters) is not recorded again: the result has recorded = false, reason = "duplicate" and the identifier of the existing analysis. An incomplete analysis, where BOLD did not return the result of some sequence (status result_missing), is not recorded either (reason = "incomplete"): otherwise the complete run with the same fingerprint would later be taken for a duplicate. Recorded analyses have reason = "recorded". Event keys are unique, so no event can be counted twice.

BOLDTrace.usage_stats — Function
usage_stats(store; project = nothing, user = nothing, analysis_id = nothing) -> NamedTuple

Counts over the recorded identification events, optionally restricted to a project, a user or one analysis (personal counter); without filters, global counter of the application:

  • n_analyses, n_projects: recorded analyses and their projects, including analyses without any BOLD match;
  • n_events (unique sequence × reference record pairs retrieved), n_lca_events (pairs in an LCA set), n_contribution_events (pairs in an LCA set of an accepted assignment);
  • n_asvs (distinct sequences, by hash), n_process_ids, n_reference_sequences (distinct reference sequence hashes; records whose sequence was not retrieved count by record key), n_process_ids_in_lca;
  • note: GLOBAL_STATS_NOTE.

The figures use the reference snapshot stored with each event, so recording later analyses (with updated BOLD metadata) never changes them.

Web application

BOLDTrace.serve — Function
serve(; database = "boldtrace.sqlite", host = "127.0.0.1", port = 8080, async = false,
      engine = () -> IDEngine(), checkpoint = "bold_checkpoint",
      portal_url = "https://portal.boldsystems.org", max_body = 64 * 2^20,
      max_records = 100_000, max_connections = 64, allowed_hosts = String[],
      max_kept = 50, max_pending = 20, defaults = LCAParams(), accept_rank = :phylum)

Start the web application (Genie.jl) on http://host:port with the usage database at database (SQLite, created if needed). Sections: Upload, Analysis, Assignments, Reference usage, Taxonomic attribution, Statistics and Export.

Analyses run one at a time in a background task and query the official BOLD v5 identification engine through engine() (rate limits of the API are respected by BOLDassignment.IDEngine). Raw BOLD results are stored in checkpoint (a directory, nothing to disable) and reused. defaults (an LCAParams) and accept_rank are the settings proposed by the page; every analysis can change them. At most max_pending analyses may be queued or running (further requests get HTTP 503). Uploads and finished analyses are kept in memory (the last max_kept of each, always including the analysis just returned); queued and running analyses are never evicted. Analyses and events are stored in the database.

With async = false the call blocks until Ctrl-C; with async = true it returns the server, stopped by shutdown. The default host accepts only local connections. There is no authentication: on a shared server use a reverse proxy with HTTPS and set allowed_hosts.

source
BOLDTrace.shutdown — Function
shutdown(server; timeout = Inf) -> Bool

Stop a server started with serve(...; async = true). New requests are refused at once; analyses still queued are cancelled; the running analysis, if any, is completed and recorded, then the database is closed. Waits at most timeout seconds for the running analysis and returns whether everything has stopped; after a timeout the database is closed as soon as the analysis ends. It acts only on the instance started by server: calling it again, or after another serve, never stops a later server.
